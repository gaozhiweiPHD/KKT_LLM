## 最优性证书的数学含义

对任意可行 y，若候选 (x, λ) 精确满足 KKT，则 $f(y)-f(x)=\lambda^\top(b-Ay)+\frac12(y-x)^\top Q(y-x)\ge0$。这里使用了 stationarity 和 complementarity；λ≥0 与 b−Ay≥0 使第一项非负，Q 正定使 y≠x 时第二项严格正。因此 x 是唯一全局最优解。
数值实验采用四项尺度归一化残差各 ≤1e-5 的近似证书，不能把它表述为精确算术证明。尺度定义及正目标/约束行缩放不变性见 README。

## RQ1–RQ4 的证据与边界

**RQ1：KKT reward 是否能 post-train active-set repair？** 实际 LoRA 更新已由参数差和日志确认。ID 成功率：zero-shot=0.00%，SFT=78.57%，GRPO-A=84.63%，GRPO-B=85.10%，GRPO-C=83.93%。参数更新本身不能证明优化能力提升；必须用这些独立终局结果与 SFT 对照。

本次单训练种子中，最佳 GRPO 相对 SFT 的 ID 成功率提高 6.53 个百分点，说明该设置下存在实际测试增益；这不等同于多训练种子上的稳健结论。

ID 行为变化（SFT→Binary）：重复状态比例 15.23%→3.90%，平均动作 10.85→10.24，非法动作率 1.48%→1.62%。成功率变化伴随着不同的多轮轨迹；非法动作同时包含语法和状态合法性错误，仅凭汇总指标不能完全拆开两者的因果贡献，后面的语法错误细分提供补充证据。

**RQ2：Residual 是否优于 Binary？** 同题测试中 B−A 的 ID 成功率差为 0.47 个百分点。下列按问题重采样的 paired bootstrap 只描述当前训练种子与测试集的不确定性，不包含重训方差。

- test_id：差值 0.47%，问题级 bootstrap 95% 区间 [-0.37%, 1.30%]。
  区间跨零，不能据此确认 Residual 优于 Binary。
- test_ood：差值 -3.33%，问题级 bootstrap 95% 区间 [-5.00%, -1.60%]。
  在当前固定训练种子的测试重采样中，Residual 的差值为负。

ID 成本惩罚检查：B→C 的平均动作数为 10.15→10.19，错误 STOP 率为 0.60%→1.20%，KKT 成功率为 85.10%→83.93%，分摊墙钟为 0.3130→0.3375 秒/题。缩短轨迹本身不作为成功，必须连同后两项判断是否存在提前停止偏好。

本次成本系数没有减少 ID 测试集的平均动作数；实际计算成本须另看保存的墙钟和 token 指标。

C 的 ID 错误 STOP 率较 B 上升，提示需要检查提前停止偏好。该判断来自实际错误 STOP 记录；不能把较短的失败路径计为优化成功，也不能从一个训练种子直接推出普遍因果结论。

## 局限与剩余工作

- 只有一个模型训练种子；多个推理种子的标准差不涵盖训练随机性。需要独立重训才能作稳健的 reward 排名。
- zero-shot 到训练模型的增益可能同时来自输出格式学习与优化决策学习；非法动作率和 SFT 对照提供部分区分，但仍需要额外的格式约束 zero-shot 消融才能完全拆开这两种作用。
- 每次动作后的等式子问题由数值模块求解，stationarity/complementarity 通常已接近机器精度；Residual Reward 的有效信号主要是 primal/dual violation。模型学习的是集合修正决策，而非线性代数求解。
- compact 模式缺少约束几何，可能导致不同 QP 的相似观察具有不同最佳动作。Oracle teacher 路径也未必能由 compact 观察唯一恢复。
- A 的奖励可能稀疏；B 的小残差改善未必足以产生有用方差；C 可能偏好短轨迹。逐组日志和错误 STOP 指标用于检查这些问题，不能靠泄漏 oracle 解决。
- n=16 与更大条件数上的失败可来自观察、索引决策、训练覆盖和 20 步截断，不能只归因于模型容量。
- 构造时乘子量级保持不变，提高 Q 条件数不保证 repair 任务更难；同时归一化 dual residual 的尺度也随 Q 改变。较高 OOD 成功率不能单独证明对病态性的鲁棒性，原始残差与容差敏感性应一起考察。
- 全信息与 thinking 模式、MLP/GNN、parametric warm start、更多训练种子未计入本次已完成实验。
- 原生 TRL 工具调用后端与主要直接文本动作后端的格式不同，提供接口实现但尚未完成端到端验证，不作为性能证据。
- classical20 与 repair Agent 使用相同上限，但每步含义不同；OSQP 没有人为 20 次迭代限制。数值 solver 对照是参考性能，不是同构策略。

所有结论以保存的实际结果为准，没有将示意数据、oracle 轨迹或其他求解器的补救结果记为模型成功。
